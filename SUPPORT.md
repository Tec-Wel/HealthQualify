## Open an issue

When reporting a **non-security** bug, include:

- Concise descriptive title and expected vs actual behavior.
- Full repository commit SHA, operating system and Python version.
- Exact CLI command and exit code.
- A **minimal synthetic** protocol, not patient data.
- The relevant sanitized test output or traceback.
- Whether you're using the strict `v05cli` runner, `appcli` workspace, `quality_cli` reviews or one-off adapter.

Before requesting a feature, confirm whether it already appears on [Roadmap](docs/ROADMAP.md) or [Open issues](https://github.com/Tec-Wel/HealthQualify/issues).

## Vulnerabilities

Do **not** publish exploit details or secrets in ordinary GitHub issues. Follow [SECURITY.md](SECURITY.md) and private GitHub advisory reporting when enabled.

## Scope reminders

No PHI, no clinical operations, no production hospital integration, no legal compliance certification and no validated e-signatures. A seeded fixture failing intentionally is **not** automatically a software defect.
